### 7.1. `src/sports_tracker/__init__.py`
Позначає каталог як Python-пакет (`package`). Забезпечує коректну роботу простору імен, містить docstring пакета та визначає глобальну константу версії застосунку:
```python

### 7.2. `src/sports_tracker/models.py`
Модуль містить визначення моделей предметної області:
- **`InvalidAthleteDataError(ValueError)`**: користувацький виняток для ситуацій, коли передані дані спортсмена не проходять валідацію (порожні рядки, від'ємне значення результату).
- **`@dataclass class Athlete`**: дата-клас, що інкапсулює стан спортсмена (`name`, `sport`, `result`, `category`). Метод `__post_init__` автоматично очищає рядки від зайвих пробілів (`.strip()`) та перевіряє коректність значень. Властивість `display_info` формує компактне рядкове представлення сутності.

### 7.3. `src/sports_tracker/services.py`
Модуль чистої бізнес-логіки. Функції не залежать від інтерфейсу вводу/виводу (`input`/`print`), приймають параметри та повертають обчислені структури даних:
- **`add_result(athletes, athlete)`**: додавання нового результату до колекції;
- **`filter_by_sport(athletes, sport)`**: фільтрація спортсменів за назвою виду спорту (нечутлива до регістру);
- **`filter_by_multiple_criteria(athletes, sport, category)`**: комплексний пошук одночасно за видом спорту та категорією;
- **`find_best_result(athletes, sport, higher_is_better)`**: пошук найкращого результату з підтримкою вибору спорту та напрямку оптимізації;
- **`calculate_average_result(athletes, sport)`**: розрахунок середнього значення результатів із округленням до 2 знаків після коми;
- **`generate_ranking(athletes, sport, descending)`**: сортування спортсменів для формування підсумкового рейтингу;
- **`calculate_statistics(athletes, sport)`**: генерація статистичного словника з полями: кількість, середнє, мінімальний і максимальний показники.

### 7.4. `src/sports_tracker/main.py`
Модуль користувацького інтерфейсу та точка входу програми:
- **`create_demo_athletes()`**: ініціалізація початкового набору даних відомими українськими спортсменами;
- **`print_athletes()`**: красиве табличне виведення списку спортсменів із вирівнюванням колонок;
- **`prompt_non_empty_string()`, `prompt_positive_float()`**: захищені функції введення даних із клавіатури, що виконують валідацію і запобігають аварійному завершенню програми при помилці користувача;
- **`print_menu()`, `run_menu()`**: реалізація циклу інтерактивного текстового меню з 8 пунктами (0–7);
- **`run_demo_scenario()`**: автоматизований прогін ключових операцій програми (викликається прапорцем `--demo`);
- **`if __name__ == "__main__": main()`**: ідіоматична конструкція безпечного запуску програми.

### 7.5. `tests/test_services.py`
Модуль для автоматичної верифікації бізнес-логіки, що тестує всі функції `services.py`, валідацію `Athlete` та генерацію винятку при некоректних даних.

### 8.1. `src/sports_tracker/models.py`
```python
"""Data models for sports results tracking."""

from dataclasses import dataclass


class InvalidAthleteDataError(ValueError):
    """Raised when athlete data fails validation."""
    pass


@dataclass
class Athlete:
    """Represents an athlete and their performance result."""

    name: str
    sport: str
    result: float
    category: str

    def __post_init__(self) -> None:
        """Validate fields after initialization."""
        self.name = self.name.strip()
        self.sport = self.sport.strip()
        self.category = self.category.strip()

        if not self.name:
            raise InvalidAthleteDataError("Athlete name cannot be empty.")
        if not self.sport:
            raise InvalidAthleteDataError("Sport name cannot be empty.")
        if not self.category:
            raise InvalidAthleteDataError("Category cannot be empty.")
        if self.result < 0:
            raise InvalidAthleteDataError(
                f"Result cannot be negative. Received: {self.result}"
            )

    @property
    def display_info(self) -> str:
        """Return formatted one-line representation."""
        return f"{self.name} | {self.sport} | {self.result:.2f} | {self.category}"
```

### 8.2. `src/sports_tracker/services.py`
```python
"""Business logic services for sports results management."""

from sports_tracker.models import Athlete

DEFAULT_PRECISION: int = 2


def add_result(athletes: list[Athlete], athlete: Athlete) -> None:
    """Add a new athlete result to the collection."""
    athletes.append(athlete)


def filter_by_sport(athletes: list[Athlete], sport: str) -> list[Athlete]:
    """Find all athletes participating in a given sport."""
    target = sport.strip().lower()
    return [a for a in athletes if a.sport.lower() == target]


def filter_by_multiple_criteria(
    athletes: list[Athlete],
    sport: str | None = None,
    category: str | None = None,
) -> list[Athlete]:
    """Filter athletes by sport and/or category."""
    result = athletes
    if sport is not None and sport.strip():
        target_sport = sport.strip().lower()
        result = [a for a in result if a.sport.lower() == target_sport]
    if category is not None and category.strip():
        target_category = category.strip().lower()
        result = [a for a in result if a.category.lower() == target_category]
    return result


def find_best_result(
    athletes: list[Athlete],
    sport: str | None = None,
    higher_is_better: bool = True,
) -> Athlete | None:
    """Determine the athlete with the best result."""
    candidates = filter_by_sport(athletes, sport) if sport else athletes
    if not candidates:
        return None
    if higher_is_better:
        return max(candidates, key=lambda a: a.result)
    return min(candidates, key=lambda a: a.result)


def calculate_average_result(
    athletes: list[Athlete],
    sport: str | None = None,
) -> float:
    """Calculate the average performance result."""
    candidates = filter_by_sport(athletes, sport) if sport else athletes
    if not candidates:
        return 0.0
    total = sum(a.result for a in candidates)
    return round(total / len(candidates), DEFAULT_PRECISION)


def generate_ranking(
    athletes: list[Athlete],
    sport: str | None = None,
    descending: bool = True,
) -> list[Athlete]:
    """Generate a sorted ranking of athletes by their performance result."""
    candidates = filter_by_sport(athletes, sport) if sport else athletes
    return sorted(candidates, key=lambda a: a.result, reverse=descending)


def calculate_statistics(
    athletes: list[Athlete],
    sport: str | None = None,
) -> dict[str, float | int]:
    """Compute summary statistics for athletes."""
    candidates = filter_by_sport(athletes, sport) if sport else athletes
    if not candidates:
        return {"count": 0, "average": 0.0, "min_result": 0.0, "max_result": 0.0}

    results = [a.result for a in candidates]
    return {
        "count": len(candidates),
        "average": round(sum(results) / len(results), DEFAULT_PRECISION),
        "min_result": min(results),
        "max_result": max(results),
    }
```

## 9. Пояснення `pyproject.toml`

Файл `pyproject.toml` є сучасним стандартом конфігурації Python-пакетів згідно зі специфікаціями **PEP 517**, **PEP 518** та **PEP 621**. Він повністю замінює традиційні імперативні файли `setup.py` і статичні `setup.cfg`.

### Вміст конфігураційного файла:
```toml
[build-system]
requires = ["setuptools>=70"]
build-backend = "setuptools.build_meta"

[project]
name = "sports-tracker"
version = "0.1.0"
description = "Sports results tracking system - Laboratory work 1 for Professional Python"
readme = "README.md"
requires-python = ">=3.11"
authors = [
    { name = "Danylo Harbiсh" }
]
keywords = ["sports", "tracker", "python", "laboratory"]
classifiers = [
    "Programming Language :: Python :: 3",
    "Programming Language :: Python :: 3.11",
    "Programming Language :: Python :: 3.12",
]

[project.scripts]
sports-tracker = "sports_tracker.main:main"
```

### Детальний розбір секцій:
1. **`[build-system]`**:
   - `requires = ["setuptools>=70"]`: вказує перелік складальних інструментів, необхідних для побудови wheel-архівів і вихідних дистрибутивів перед початком збирання.
   - `build-backend = "setuptools.build_meta"`: визначає програмний бекенд для збирання. Уніфікований інтерфейс дозволяє менеджеру `pip` коректно зібрати та встановити пакет у будь-якому оточенні.
2. **`[project]`**:
   - `name = "sports-tracker"`: офіційне ім'я дистрибутива в реєстрі пакетів;
   - `version = "0.1.0"`: номер версії за семантичним версіонуванням (`SemVer`);
   - `description`: короткий опис призначення проєкту;
   - `readme = "README.md"`: файл повної документації, що відображатиметься на головній сторінці пакета;
   - `requires-python = ">=3.11"`: декларація мінімальної версії інтерпретатора Python;
   - `authors`: відомості про розробника проєкту;
   - `classifiers`: стандартизовані метадані для категоризації проєкту за мовою та її версіями.
3. **`[project.scripts]`**:
   - `sports-tracker = "sports_tracker.main:main"`: реєстрація консольної утиліти (CLI). Під час інсталяції проєкту (зокрема, через `pip install -e .`) система автоматично створює виконуваний скрипт `sports-tracker` у каталозі віртуального середовища (`.venv/Scripts/`), пов'язаний безпосередньо з викликом функції `main()` з модуля `sports_tracker.main`.

**Індивідуальний варіант №9:** «Облік спортивних результатів».

## Встановлення (Installation)

1. Клонуйте репозиторій або відкрийте каталог проєкту у терміналі:
   ```bash
   cd lab1
   ```

2. Створіть віртуальне середовище:
   ```bash
   python -m venv .venv
   ```

3. Активуйте віртуальне середовище:
   - **Windows (PowerShell)**: `.venv\Scripts\activate`
   - **Linux / macOS**: `source .venv/bin/activate`

4. Встановіть проєкт у режимі редагування:
   ```bash
   python -m pip install -e .
   ```

## Запуск програми (Run)

- Запуск через модуль: `python -m sports_tracker.main`
- Запуск через консольну команду: `sports-tracker`
- Запуск автоматичної демонстрації: `python -m sports_tracker.main --demo`
- Запуск тестів: `python tests/test_services.py`
```

## 15. Відповіді на контрольні запитання

### 1. Що таке Python-проєкт?
**Відповідь:** Python-проєкт — це організована сукупність файлів вихідного коду, пакетів, конфігураційних файлів, документації, автоматизованих тестів та списку залежностей, що об'єднані для вирішення конкретної задачі як самостійна програмна система чи бібліотека.

### 2. Чим проєкт відрізняється від одного Python script?
**Відповідь:** Скрипт — це один автономний `.py`-файл з лінійними інструкціями для локального виконання. Проєкт має модульну архітектуру, систему керування залежностями, ізольоване оточення (`.venv`), стандартну систему збірки (`pyproject.toml`), контроль версій (Git) та можливість пакування й поширення через інструменти на кшталт `pip`.

### 3. Що таке Python module?
**Відповідь:** Python-модуль — це файл із розширенням `.py`, який містить визначення функцій, класів або змінних і призначений для повторного використання в інших модулях через механізм імпортування (`import`).

### 4. Що таке Python package?
**Відповідь:** Python-пакет — це каталог, що містить один або більше модулів (або вкладених пакетів) та службовий файл `__init__.py`, який забезпечує ієрархічне структурування простору імен.

### 5. Для чого потрібний `__init__.py`?
**Відповідь:** Файл `__init__.py` сигналізує інтерпретатору Python, що даний каталог є пакетом. Він виконується під час імпорту пакета і дозволяє задавати версію (`__version__`), налаштовувати скорочені імпорти та керувати публічним інтерфейсом через список `__all__`.

### 6. Що таке src-layout?
**Відповідь:** `src-layout` — це стандарт структури проєкту, за якого весь вихідний програмний код розташовується у спеціальній піддиректорії `src/` (наприклад, `src/sports_tracker/`), а не безпосередньо в корені репозиторію поруч із конфігураційними файлами.

### 7. Які переваги має src-layout?
**Відповідь:** Головна перевага — унеможливлення випадкового імпортування локального незібраного коду при тестуванні. Тести запускаються проти встановленого у віртуальне середовище пакета, що відтворює реальні умови кінцевого користувача. Також це запобігає появі зайвих артефактів (`__pycache__`) у кореневій папці проєкту.

### 8. Для чого використовується virtual environment?
**Відповідь:** Віртуальне середовище забезпечує ізоляцію бібліотек та їхніх версій для конкретного проєкту. Воно гарантує, що встановлення чи оновлення пакетів в одному проєкті не порушить працездатність інших проєктів або системного інтерпретатора Python.

### 9. Як створити `.venv`?
**Відповідь:** Використовуючи стандартний вбудований модуль `venv`:
```bash
python -m venv .venv
```

### 10. Як активувати virtual environment?
**Відповідь:**
- У Windows (PowerShell): `.venv\Scripts\activate`
- У Windows (Command Prompt): `.venv\Scripts\activate.bat`
- У Linux / macOS: `source .venv/bin/activate`

### 11. Для чого використовується pip?
**Відповідь:** `pip` — це стандартний менеджер пакетів для Python, призначений для встановлення, оновлення, видалення та інспектування сторонніх бібліотек з репозиторію PyPI або локальних дистрибутивів.

### 12. Чому рекомендується `python -m pip`?
**Відповідь:** Виклик `python -m pip` явно запускає модуль `pip`, асоційований саме з поточним активним інтерпретатором `python`. Це виключає ризик звернення до глобального системного `pip` або іншої версії Python, прописаної у змінній середовища `PATH`.

### 13. Для чого потрібний `pyproject.toml`?
**Відповідь:** `pyproject.toml` — це єдиний сучасний декларативний конфігураційний файл проєкту (PEP 517, 518, 621), що визначає систему збирання, метадані (назву, версію, автора, ліцензію, залежності) та параметри лінтерів, форматтерів і тестових фреймворків.

### 14. Що містить секція `[project]`?
**Відповідь:** Секція `[project]` стандартизує метадані пакета: назву (`name`), версію (`version`), короткий опис (`description`), файл опису (`readme`), сумісні версії Python (`requires-python`), список залежностей (`dependencies`), а також точки входу для консольних команд (`[project.scripts]`).

### 15. Що таке editable installation?
**Відповідь:** Встановлення в режимі редагування (`pip install -e .` або `--editable`). Замість копіювання файлів до `site-packages`, у віртуальному середовищі створюється посилання на робочий каталог `src/`. Будь-які зміни у коді відразу стають доступними без повторного виконання інсталяції.

### 16. Для чого використовується `if __name__ == "__main__":`?
**Відповідь:** Конструкція перевіряє, чи файл запущено як основну програму (`__name__ == "__main__"`), чи він імпортований як модуль іншим скриптом. Це дозволяє уникнути автоматичного виконання виконуваного коду або запуску консольного інтерфейсу під час імпорту функцій для тестування.

### 17. Що таке Git?
**Відповідь:** Git — це розподілена система керування версіями файлів, яка фіксує історію змін проєкту, дає змогу повертатися до будь-якого попереднього стану коду, вести розробку в окремих гілках та ефективно співпрацювати над кодом у команді.

### 18. Що таке repository?
**Відповідь:** Репозиторій — це спеціальне сховище Git (каталог `.git`), де зберігається повна історія комітів, гілок, тегів, конфігурацій та метаданих, що описують усі зміни проєкту.

### 19. Що таке commit?
**Відповідь:** Коміт — це збережений у базі даних Git моментальний знімок (снапшот) стану проіндексованих файлів проєкту в певний момент часу. Кожен коміт має унікальний хеш-ідентифікатор, дату, автора та змістовне повідомлення про внесені зміни.

### 20. Для чого використовується `git status`?
**Відповідь:** Команда `git status` відображає поточний стан робочого каталогу та індексу (staging area): які файли модифіковано, які підготовлено до коміту, а які не відстежуються системою контролю версій.

### 21. Для чого `git add`?
**Відповідь:** Команда `git add` додає вказані файли чи зміни з робочої директорії до області індексації (staging area), формуючи набір змін для наступного коміту.

### 22. Для чого `git commit`?
**Відповідь:** Команда `git commit` остаточно записує підготовлені в індексі зміни до історії репозиторію, створюючи новий коміт із зазначеним повідомленням (`-m`).

### 23. Що показує `git log`?
**Відповідь:** Команда `git log` виводить хронологічну історію комітів поточної гілки. Прапорець `--oneline` дозволяє переглядати історію у компактному однорядковому форматі: скорочений хеш і тема повідомлення.

### 24. Для чого потрібен `.gitignore`?
**Відповідь:** Файл `.gitignore` містить шаблони імен файлів та директорій, які Git повинен ігнорувати. Це запобігає потраплянню до репозиторію кешів, бінарних файлів, конфіденційних даних (`.env`), файлів середовищ (`.venv/`) та службових каталогів IDE.

### 25. Чому `.venv` не потрібно комітити?
**Відповідь:** Каталог `.venv` містить велику кількість платформозалежних бінарних файлів і бібліотек, прив'язаних до конкретної операційної системи та шляхів на диску комп'ютера розробника. На іншій машині таке середовище не працюватиме. Замість коміту `.venv` у репозиторій додають декларативні файли залежностей (`pyproject.toml`), що дозволяє відтворити оточення з нуля на будь-якій ОС.

### 26. Для чого потрібний README?
**Відповідь:** `README.md` — це основний документ проєкту, який знайомить розробників і користувачів із його призначенням, архітектурою, системними вимогами, інструкціями зі встановлення, запуску, тестування та прикладами використання.

### 27. Що таке type hints?
**Відповідь:** Анотації типів (type hints) — синтаксичний механізм мови Python (PEP 484), що дозволяє вказувати очікувані типи аргументів функцій, типів повернення та атрибутів. Вони полегшують читання коду, покращують автодоповнення в IDE та дозволяють виконувати статичний аналіз коду інструментами на зразок `mypy`.

### 28. Для чого програму розділяють на modules?
**Відповідь:** Розділення програми на модулі забезпечує принцип слабкої зв'язаності (low coupling) та високої функціональної цілісності (high cohesion). Модульність спрощує навігацію кодовою базою, полегшує внесення змін, усуває дублювання коду та дозволяє ізольовано тестувати окремі підсистеми.

### 29. Що таке business logic?
**Відповідь:** Бізнес-логіка (business logic) — це ядро застосунку, яке інкапсулює правила обробки даних, розрахунки, алгоритми фільтрації та обмеження предметної області, залишаючись абсолютно незалежним від користувацького інтерфейсу чи джерел збереження даних.

### 30. Чому потрібно відокремлювати application entry point від business logic?
**Відповідь:** Відокремлення точки входу (UI/CLI/API) від бізнес-логіки реалізує архітектурний принцип єдиної відповідальності (Single Responsibility Principle). Завдяки цьому функції логіки стають детермінованими («чистими»), їх легко тестувати автоматичними тестами без імітації консольного вводу (`input()`), а також це дає змогу змінити інтерфейс програми (наприклад, створити web-версію чи REST API) без модифікації обчислювального ядра.
