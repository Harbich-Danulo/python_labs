5. Опис предметної області

Предметна область охоплює облік та аналіз досягнень спортсменів у різноманітних дисциплінах:

  • Вид спорту (Sport): визначає назву дисципліни («Біг на 100м», «Плавання 50м», «Стрибки у довжину»), одиницю вимірювання («сек», «м») та критерій першості is_lower_better (для бігу менший час є кращим результатом, для стрибків — навпаки).
  • Спортсмен (Athlete): містить персональні дані атлета (повне ім'я, країна/клуб, вік).
  • Результат (Result): фіксує виступ конкретного спортсмена у конкретній дисципліні, числовий бал (score > 0), вікову/кваліфікаційну категорію («Юніори», «Дорослі», «Фінал») та назву змагань (competition_name).

    category: str = Field(..., min_length=2, max_length=50)

13. Validation rules

  • Ім'я атлета (name): довжина від 2 до 150 символів, заборонені порожні рядки.
  • Вік спортсмена (age): обмеження ge=5, le=120 (від 5 до 120 років).
  • Результат (score): суворо більше нуля (gt=0.0). Негативні або нульові показники відхиляються з кодом 422.
  • Зовнішні ключі (athlete_id, sport_id): перевіряється їхнє реальне існування в базі даних (у разі відсутності повертається статус 404).
  • Унікальність назви дисципліни: спроба зареєструвати існуючий вид спорту генерує код 409 Conflict.

    results = await asyncio.wait_for(
        asyncio.gather(*tasks, return_exceptions=False),
        timeout=timeout,
    )
except asyncio.TimeoutError as exc:
    for t in tasks:
        if not t.done():
            t.cancel()
    raise ExternalServiceError(f"Перевищено ліміт часу виконання {timeout} с.") from exc

32. Відповіді на контрольні запитання (Розділ 64)

1. Що таке комп'ютерна мережа?

Комп'ютерна мережа — це сукупність взаємопов'язаних вузлів (комп'ютерів, серверів, терміналів), з'єднаних каналами зв'язку, що використовують стандартизовані комунікаційні протоколи для взаємного обміну даними та спільного доступу до ресурсів.

2. Що таке клієнт-серверна архітектура?

Клієнт-серверна архітектура — це модель розподіленої взаємодії, у якій клієнт генерує та надсилає запит, а сервер опрацьовує його, виконує необхідні бізнес-операції зі сховищем даних і формує структуровану відповідь.

3. Що таке HTTP?

HTTP (HyperText Transfer Protocol) — прикладний мережевий протокол передачі структурованих повідомлень (HTML, JSON, бінарних даних) за моделлю «запит-відповідь» (Request-Response), що є технологічною основою функціонування сучасного інтернету.

4. Що містить HTTP request?

HTTP request містить стартовий рядок (HTTP-метод, шлях URI, версію протоколу), набір заголовків (Headers) та опціональне тіло повідомлення (Body).

5. Що містить HTTP response?

HTTP response містить рядок статусу (версія протоколу, числовий код стану Status Code, текстовий опис причини), службові заголовки та тіло відповіді (переважно JSON або HTML).

6. Для чого використовується GET?

Метод GET використовується для отримання та зчитування даних із сервера без будь-якої зміни його стану (безпечний та ідемпотентний метод).

7. Для чого використовується POST?

Метод POST використовується для надсилання інформації на сервер з метою створення нового ресурсу або ініціювання неідемпотентної операції.

8. Для чого використовується PUT?

Метод PUT використовується для повного заміщення (перезапису) існуючого ресурсу або його створення за вказаною URL-адресою (ідемпотентний метод).

9. Для чого використовується PATCH?

Метод PATCH використовується для часткової модифікації окремих полів існуючого ресурсу без передачі його повного стану.

10. Для чого використовується DELETE?

Метод DELETE використовується для видалення вказаного ресурсу за його унікальним URI.

11. Що означає status code 200?

200 OK свідчить про успішну обробку запиту (зазвичай при операціях GET, PATCH або успішній обробці).

12. Що означає 201?

201 Created вказує на те, що в результаті виконання запиту (переважно POST) успішно створено новий ресурс.

13. Що означає 204?

204 No Content означає успішне виконання запиту сервером за відсутності вмісту в тілі відповіді (стандарт для операції DELETE).

14. Що означає 404?

404 Not Found свідчить про те, що зазначений у запиті ресурс не знайдено на сервері.

15. Що означає 422?

422 Unprocessable Entity виникає, коли синтаксис запиту валідний, проте дані не відповідають бізнес-правилам або типам валідатора (стандарт FastAPI/Pydantic).

16. Що таке JSON?

JSON (JavaScript Object Notation) — загальноприйнятий легкочитний текстовий формат серіалізації даних у вигляді пар ключ-значення та масивів.

17. Що таке REST?

REST (Representational State Transfer) — архітектурний стиль побудови розподілених веб-сервісів, орієнтований на ресурси, протокол HTTP, уніфіковані інтерфейси та відсутність збереження стану сесії клієнта (Stateless).

18. Що таке resource у REST?

Ресурс у REST — це концептуальний об'єкт предметної області, що має однозначний унікальний ідентифікатор URI (наприклад, спортсмен або рейтинг дисципліни).

19. Що таке endpoint?

Endpoint — це конкретна точка доступу веб-інтерфейсу, що складається з URL-шляху та прив'язаного HTTP-методу.

20. Що таке path parameter?

Path parameter — змінний фрагмент маршруту URL (наприклад, /athletes/{id}), що вказує на конкретний екземпляр ресурсу.

21. Що таке query parameter?

Query parameter — необов'язковий параметр у кінці URL після символу ? (наприклад, ?country=Україна) для фільтрації, пагінації чи сортування.

22. Що таке request body?

Request body — корисне навантаження запиту (переважно у форматі JSON), що передає параметри для створення або зміни об'єкта.

23. Що таке FastAPI?

FastAPI — сучасний, продуктивний веб-фреймворк для розробки REST API на базі стандартних анотацій типів Python, Pydantic, Starlette та повної підтримки асинхронності.

24. Для чого використовується Uvicorn?

Uvicorn — це високошвидкісний асинхронний ASGI-сервер, який запускає додаток FastAPI та керує мережевими HTTP-з'єднаннями.

25. Для чого потрібний Swagger UI?

Swagger UI автоматично формує вебінтерфейс для інтерактивного перегляду, навігації та надсилання тестових запитів до всіх ендпоінтів REST API безпосередньо у браузері.

26. Що таке Pydantic?

Pydantic — бібліотека Python для парсингу, суворої типізації, серіалізації та валідації структур даних.

27. Що таке validation?

Валідація — це автоматизований контроль коректності структури та семантики вхідних даних відповідно до задекларованих обмежень і бізнес-правил.

28. Що таке response model?

Response model — схема Pydantic, яка фільтрує внутрішні поля моделі, гарантує повернення клієнту лише дозволених атрибутів та генерує схему в документації OpenAPI.

29. Що таке synchronous programming?

Синхронне програмування — парадигма послідовного виконання, де кожна операція повністю блокує потік до моменту свого завершення.

30. Що таке asynchronous programming?

Асинхронне програмування — парадигма неблокуючого конкурентного виконання в межах одного потоку, коли час очікування операцій введення-виведення використовується для виконання інших завдань.

31. Для чого використовується async?

Ключове слово async позначає функцію як корутину (coroutine), сигналізуючи інтерпретатору про її здатність до асинхронного виконання.

32. Для чого використовується await?

Ключове слово await призупиняє виконання поточної корутини та передає керування циклу подій до моменту завершення операції, що очікується.

33. Що таке coroutine?

Корутина — це спеціалізована функція, яка може призупиняти свій стан у точках await та відновлювати роботу пізніше за сигналом Event Loop.

34. Що таке event loop?

Event loop (цикл подій) — центральний керуючий механізм середовища asyncio, що реєструє події, відстежує дескриптори вводу-виводу та диспетчеризує чергу завдань.

35. Що таке Task?

asyncio.Task — об'єкт, що планує та представляє виконання окремої корутини в циклі подій, дозволяючи відстежувати її статус та очікувати результат.

36. Для чого використовується asyncio.create_task()?

asyncio.create_task() використовується для створення об'єкта Task та планування негайного конкурентного виконання корутини у фоновому режимі.

37. Для чого використовується asyncio.gather()?

asyncio.gather() використовується для конкурентного паралельного виконання списку корутин/завдань та збору їхніх результатів в єдиний список.

38. Що таке timeout?

Timeout — максимальний дозволений інтервал часу для виконання мережевої операції, після якого генерується виключення для запобігання нескінченному зависанню.

39. Для чого потрібний retry?

Retry забезпечує автоматичне повторення мережевого запиту в разі короткочасних транзитних збоїв (мережеві помилки, тимчасова недоступність хоста).

40. Що таке backoff?

Backoff — алгоритмічна пауза між повторними запитами (зазвичай експоненційна), що запобігає перевантаженню відновлюваного сервісу штормом запитів.

41. Для чого використовується Semaphore?

asyncio.Semaphore встановлює ліміт максимальної кількості корутин, що можуть одночасно виконувати операції з ресурсом (наприклад, не більше 3 одночасних запитів).

42. Що таке HTTPX?

HTTPX — сучасна бібліотека Python для виконання синхронних та асинхронних HTTP-запитів із підтримкою HTTP/1.1, HTTP/2 та повної інтеграції з asyncio.

43. Чим httpx.AsyncClient відрізняється від синхронного клієнта?

httpx.AsyncClient використовує неблокуючі системні виклики та сокети, не блокуючи потік виконання програми під час очікування мережевої відповіді.

44. Чому AsyncClient бажано повторно використовувати?

Повторне використання клієнта задіює пул TCP-з'єднань (Connection Pooling), уникаючи повторних дорогих витрат на TCP/TLS Handshake на кожен окремий запит.

45. Навіщо обмежувати паралелізм?

Обмеження паралелізму запобігає вичерпанню сокетів операційної системи, перевищенню лімітів запитів (Rate Limiting) та падінню продуктивності сервера від надмірного навантаження.

46. Чому не слід запускати тисячі tasks одночасно?

Масовий запуск тисяч тасок може вичерпати системні дескриптори відкритих файлів/сокетів, переповнити пам'ять та спричинити відмову в обслуговуванні (DoS).

47. Як REST API взаємодіє з Repository Layer?

Маршрутизатор FastAPI отримує сесію бази даних через механізм Depends(get_session), передає її в Service Layer, який делегує репозиторіям виконання SQL-запитів до бази даних.

48. Як FastAPI працює з Pydantic?

FastAPI аналізує сигнатури ендпоінтів: якщо тип аргументу успадковано від BaseModel, фреймворк автоматично десеріалізує JSON-тіло, валідує його та генерує схему OpenAPI.

49. Як протестувати REST API?

REST API тестують за допомогою тест-раннера pytest, клієнтів TestClient або httpx.AsyncClient з ізольованою in-memory тестовою базою даних, перевіряючи коди статусів та структури відповідей.

50. Чим API integration test відрізняється від unit test?

Unit test перевіряє ізольовану функцію із підміною залежностей на mock-об'єкти, а API integration test перевіряє наскрізну роботу всієї системи від HTTP-запиту через валідацію, сервіс і репозиторій до реальної бази даних.
