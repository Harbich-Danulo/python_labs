## 7. Пояснення вибору `list`, `tuple`, `set`, `dict`

1. **`list` (`athletes: list[dict]`)**:
   - *Чому обрано*: змінювана впорядкована колекція. Забезпечує легке додавання записів через `append()` за час $O(1)$, послідовну ітерацію, збереження порядку та роботу з індексами при сортуванні.
2. **`tuple` (`meta: tuple[str, str, int]`)**:
   - *Чому обрано*: незмінна структура фіксованої довжини. Метадані запису (наприклад, `("WR", "Україна", 2024)`) логічно утворюють цілісний кортеж, що не повинен випадково модифікуватися окремими полями. Кортежі ефективніші за пам'яттю, ніж списки.
3. **`set` (`sports_set: set[str]`)**:
   - *Чому обрано*: колекція унікальних хешованих значень. Дозволяє миттєво відкинути дублікати видів спорту чи категорій, а перевірка входження `item in set` виконується за середній час $O(1)$ замість $O(n)$ у списку. Забезпечує підтримку математичних операцій (об'єднання `|`, перетин `&`, різниця `-`).
4. **`dict` (`id_index: dict[int, dict]`)**:
   - *Чому обрано*: асоціативна таблиця пар ключ-значення, побудована на хеш-таблиці. Використовується як для представлення окремого складного об'єкта зі структурованими атрибутами, так і для побудови індексів швидкого пошуку (`index[id]`) за час $O(1)$.

## 8. Приклад використання `collections`

У проєкті використано три структури модуля `collections`:
1. **`collections.Counter`**:
   - Підрахунок розподілу спортсменів за дисциплінами та категоріями в один рядок:
   ```python
   sport_counts = Counter(item["sport"] for item in records)
   ```
2. **`collections.defaultdict`**:
   - Групування спортсменів без необхідності перевіряти наявність ключа за допомогою `if key not in dict`:
   ```python
   groups = defaultdict(list)
   for item in records:
       groups[item["sport"]].append(item)
   ```
   - Вкладене дворівневе групування (вид спорту $\to$ категорія $\to$ список):
   ```python
   nested = defaultdict(lambda: defaultdict(list))
   ```
3. **`collections.deque`**:
   - Двобічна черга фіксованого розміру `deque(maxlen=20)` для ведення кільцевого буфера аудиту та історії виконаних операцій.

## 15. Пояснення `closure` (замикання)

Замикання (`closure`) — це функція, яка запам'ятовує змінні зі свого лексичного контексту (зовнішньої функції) навіть після завершення виконання зовнішньої функції.

```python
def create_category_filter(category: str) -> Callable[[dict[str, Any]], bool]:
    target = category.strip().lower()  # Змінна зберігається в замиканні

    def predicate(athlete: dict[str, Any]) -> bool:
        return athlete["category"].strip().lower() == target  # Доступ до target
    return predicate

# Використання:
filter_senior = create_category_filter("Дорослі")
seniors = [a for a in athletes if filter_senior(a)]
```
*Пояснення*: Функція `create_category_filter` завершила виконання, проте повернута функція `predicate` утримує посилання на змінну `target` у своїй внутрішній комірці пам'яті (`__closure__`).

## 16. Пояснення `decorator` (декоратор)

Декоратор — це функція вищого порядку, яка приймає іншу функцію як аргумент, додає до неї додаткову поведінку (проксіює виклик) і повертає оновлену функцію, не модифікуючи вихідний код оригіналу.

```python
def measure_time(func: Callable[..., Any]) -> Callable[..., Any]:
    @wraps(func)
    def wrapper(*args: Any, **kwargs: Any) -> Any:
        start_time = perf_counter()
        result = func(*args, **kwargs)
        elapsed = perf_counter() - start_time
        print(f"[TIMING] {func.__name__}: {elapsed:.8f} s")
        operation_history.append(f"{func.__name__} executed in {elapsed:.8f} s")
        return result
    return wrapper
```
*Пояснення*:
1. `@wraps(func)` зберігає ім'я функції (`__name__`) та документацію (`__doc__`).
2. `*args`, `**kwargs` роблять декоратор універсальним для будь-якої сигнатури.
3. Додаткова функціональність: вимірювання часу виконання та автоматичний запис операції в чергу `deque`.

Також реалізовано параметризований декоратор `@repeat(count=2)`, що виконує дію вказану кількість разів.

## 18. Таблиця складності операцій (Big-O)

| Операція | Структура даних | Складність у середньому | Складність у гіршому випадку | Пояснення |
| :--- | :--- | :--- | :--- | :--- |
| Пошук за ID перебором | `list` | $O(n)$ | $O(n)$ | Лінійне сканування елементів списку до знаходження збігу |
| Пошук за ID через хеш-індекс | `dict` | $O(1)$ | $O(n)$ | Обчислення хешу ключа дає миттєвий прямий доступ до комірки пам'яті |
| Перевірка наявності елемента | `set` | $O(1)$ | $O(n)$ | Хеш-пошук у множині унікальних ключів |
| Сортування за результатом | `list` (Timsort) | $O(n \log n)$ | $O(n \log n)$ | Гібридний алгоритм сортування злиттям і вставками Python Timsort |
| Додавання в кінець (`append`) | `list` | $O(1)$ | $O(n)$ | Амортизований константний час (зрідка перевиділення пам'яті) |
| Додавання / вилучення з кінців | `deque` | $O(1)$ | $O(1)$ | Двозв'язний список блоків пам'яті |

## 19. Результати Benchmark

Експериментальне порівняння часу виконання лінійного пошуку в `list` проти пошуку за ключем у хеш-індексі `dict`:

| Кількість записів ($n$) | Час пошуку в `list` ($O(n)$) | Час пошуку в `dict` ($O(1)$) | Фактичне прискорення |
| :--- | :--- | :--- | :--- |
| **1 000** | 0.00002960 с | 0.00000040 с | **74.0×** |
| **10 000** | 0.00028760 с | 0.00000110 с | **261.5×** |
| **100 000** | 0.00314190 с | 0.00000790 с | **397.7×** |

### Аналіз зв'язку між теоретичною складністю та практичним часом:
1. **Лінійне зростання для `list`**: зі збільшенням кількості записів у 10 разів (від 1 000 до 10 000 та від 10 000 до 100 000) час лінійного пошуку зростає приблизно в 10 разів (0.00003 с $\to$ 0.00029 с $\to$ 0.00314 с), що повністю підтверджує теоретичну оцінку $O(n)$.
2. **Константна поведінка для `dict`**: час пошуку в словнику залишається в діапазоні мікросекунд навіть на 100 000 елементів, підтверджуючи амортизовану складність $O(1)$.
3. **Висновок**: попередня побудова індексу `dict` $O(n)$ окупає себе вже після кількох запитів, прискорюючи регулярний пошук у сотні разів на великих масивах даних.

## 20. Контрольні запитання

### 1. Що таке list?
**Відповідь:** `list` — це вбудована у Python впорядкована, динамічна та змінювана (`mutable`) послідовність довільних об'єктів із доступом за цілочисловим індексом.

### 2. Чим list відрізняється від tuple?
**Відповідь:** `list` є змінюваним (`mutable`), тобто його розмір та елементи можна змінювати на місці (`append`, `pop`). `tuple` є незмінним (`immutable`) після створення. Через це кортежі споживають менше пам'яті, працюють швидше і можуть бути ключами у `dict` та елементами у `set`.

### 3. Чому tuple називається immutable?
**Відповідь:** Тому що внутрішній стан об'єкта `tuple` фіксується в момент створення у пам'яті і не надає методів для додавання, видалення чи перепризначення посилань на його елементи.

### 4. Для чого використовується set?
**Відповідь:** Множина `set` використовується для збереження невпорядкованої колекції унікальних елементів, швидкої перевірки належності `x in s` за час $O(1)$ та виконання операцій теорії множин (об'єднання, перетин, різниця).

### 5. Яка властивість елементів set є важливою?
**Відповідь:** Усі елементи `set` обов'язково повинні бути хешованими (`hashable`), тобто мати незмінний хеш-код протягом усього життя об'єкта (реалізовувати метод `__hash__`) та підтримувати перевірку на рівність (`__eq__`).

### 6. Що таке dict?
**Відповідь:** `dict` — це вбудована асоціативна структура даних, що зберігає інформацію у вигляді пар «ключ — значення» (`key: value`) з високоефективним доступом до значень за їхніми ключами.

### 7. Що таке key-value structure?
**Відповідь:** Структура «ключ-значення» — це спосіб організації даних, де кожному унікальному ідентифікатору (ключу) відповідає певний об'єкт (значення), за аналогією зі словником або телефонною книгою.

### 8. Чому пошук key у dict зазвичай швидкий?
**Відповідь:** `dict` реалізовано на основі хеш-таблиці. Позиція елемента в пам'яті визначається безпосередньо обчисленням хеш-функції від ключа `hash(key) % size`, що забезпечує прямий доступ за час $O(1)$ без послідовного перебору елементів.

### 9. Що таке hashability?
**Відповідь:** Хешованість (`hashability`) — це властивість об'єкта мати незмінне числове хеш-значення, яке повертається функцією `hash()`, що дозволяє використовувати його як ключ у `dict` або елемент у `set`.

### 10. Чому list не може бути key у dict?
**Відповідь:** `list` є змінюваною (`mutable`) структурою даних і не реалізує метод `__hash__`. Якби список можна було використати як ключ, а потім змінити його вміст, його хеш змінився б, і об'єкт стало б неможливо знайти за старим місцем у хеш-таблиці.

### 11. Для чого використовується Counter?
**Відповідь:** `collections.Counter` — це спеціалізований підклас словника, призначений для швидкого та зручного підрахунку кількості появ повторюваних елементів у послідовностях.

### 12. Для чого використовується defaultdict?
**Відповідь:** `collections.defaultdict` автоматично ініціалізує та повертає значення за замовчуванням (викликаючи передану функцію-фабрику, наприклад `list` або `int`), якщо запитуваний ключ ще відсутній у словнику, уникаючи виникнення помилки `KeyError`.

### 13. Для чого використовується deque?
**Відповідь:** `collections.deque` (двозбічна черга) оптимізована для швидкого додавання та видалення елементів з обох кінців (`append`, `appendleft`, `pop`, `popleft`) за гарантований час $O(1)$, на відміну від списку, де операції з початком вимагають зсуву за час $O(n)$.

### 14. Що таке list comprehension?
**Відповідь:** Це компактний ідіоматичний синтаксис для створення нових списків шляхом обходу ітерованого об'єкта з можливістю застосування перетворень та фільтрації: `[expr for item in iterable if cond]`.

### 15. Що таке set comprehension?
**Відповідь:** Синтаксична конструкція для формування множини унікальних елементів у виразі: `{expr for item in iterable if cond}`.

### 16. Що таке dict comprehension?
**Відповідь:** Синтаксична конструкція для формування словника з виразів пар ключ-значення: `{key_expr: val_expr for item in iterable if cond}`.

### 17. Що таке generator expression?
**Відповідь:** Генераторний вираз `(expr for item in iterable)` створює лінивий ітератор, який повертає значення по одному за запитом, не генеруючи всю колекцію в оперативній пам'яті одночасно.

### 18. Що означає O(1)?
**Відповідь:** Константна часова складність — час виконання операції не залежить від обсягу вхідних даних $n$ і залишається практично незмінним.

### 19. Що означає O(n)?
**Відповідь:** Лінійна часова складність — час виконання операції зростає прямо пропорційно до кількості елементів $n$.

### 20. Що означає O(n log n)?
**Відповідь:** Лінійно-логарифмічна складність — характерна для оптимальних алгоритмів порівняльного сортування (наприклад, Timsort у Python).

### 21. Що означає O(n²)?
**Відповідь:** Квадратична часова складність — час виконання зростає пропорційно квадрату обсягу даних (типово для вкладених циклів по тій самій вибірці).

### 22. Яка приблизна складність пошуку у list?
**Відповідь:** $O(n)$, оскільки в несортованому списку інтерпретатор повинен послідовно порівняти кожен елемент із шуканим значенням.

### 23. Яка середня складність пошуку у set?
**Відповідь:** $O(1)$ у середньому завдяки механізму адресації за хеш-кодом.

### 24. Яка середня складність пошуку key у dict?
**Відповідь:** $O(1)$ у середньому за рахунок прямого обчислення індексу в хеш-таблиці.

### 25. Чому правильна структура даних може прискорити програму?
**Відповідь:** Вибір структури з меншою алгоритмічною складністю (наприклад, заміна пошуку в `list` $O(n)$ на пошук у `dict` чи `set` $O(1)$) знижує кількість необхідних процесорних інструкцій на порядки при зростанні обсягу даних.

### 26. Що таке функціональна декомпозиція?
**Відповідь:** Це процес розбиття великої монолітної задачі або функції на невеликі, незалежні, логічно ізольовані підфункції, кожна з яких вирішує рівно одне конкретне підзавдання.

### 27. Які переваги малих functions?
**Відповідь:** Малі функції легко читати, тестувати за допомогою автоматизованих юніт-тестів, повторно використовувати в інших частинах коду та модифікувати без ризику зламати суміжні модулі.

### 28. Що таке positional argument?
**Відповідь:** Позиційний аргумент — це значення, що передається у функцію відповідно до його черговості (позиції) у списку параметрів виклику.

### 29. Що таке keyword argument?
**Відповідь:** Іменований аргумент — це значення, що передається із зазначенням імені параметра (`name=value`), що дозволяє передавати їх у довільному порядку та підвищує читабельність.

### 30. Для чого використовується *args?
**Відповідь:** Синтаксис `*args` дозволяє функції приймати довільну змінну кількість позиційних аргументів, які всередині функції стають доступними як кортеж (`tuple`).

### 31. Для чого використовується **kwargs?
**Відповідь:** Синтаксис `**kwargs` дозволяє функції приймати довільну кількість іменованих аргументів, які всередині функції стають доступними як словник (`dict`).

### 32. Що таке lambda function?
**Відповідь:** Це коротка анонімна функція, визначена за допомогою ключового слова `lambda`, що складається з одного виразу, результат якого автоматично повертається: `lambda x: x * 2`.

### 33. Де доцільно використовувати lambda?
**Відповідь:** Як короткі одноразові функції-колбеки у функціях вищого порядку: як ключ сортування (`key=lambda x: ...`), у предикатах фільтрації або математичних перетвореннях.

### 34. Чому складну business logic не варто записувати в lambda?
**Відповідь:** Тому що `lambda` обмежена одним рядком/виразом, не може містити розгалужень зі складними блоками інструкцій, не має власного імені для трасування помилок та значно погіршує читабельність коду.

### 35. Що таке closure?
**Відповідь:** Замикання (`closure`) — це внутрішня функція, яка зберігає зв'язок зі змінними зовнішньої функції з її області видимості навіть після того, як зовнішня функція завершила своє виконання.

### 36. Які variables може пам'ятати closure?
**Відповідь:** Будь-які нелокальні змінні (`nonlocal variables`), визначені в тілі зовнішньої функції, до яких внутрішня функція звертається у своєму тілі.

### 37. Що таке decorator?
**Відповідь:** Декоратор — це функція вищого порядку, яка огортає іншу функцію для модифікації або розширення її поведінки без зміни її вихідного коду.

### 38. Для чого застосовуються decorators?
**Відповідь:** Для наскрізної функціональності (cross-cutting concerns): профілювання та вимірювання часу виконання, логування, кешування результатів, валідації прав доступу, повторних спроб виконання (`retry`) тощо.

### 39. Для чого використовується functools.wraps?
**Відповідь:** Декоратор `@wraps` копіює метадані вихідної функції (ім'я `__name__`, docstring `__doc__`, анотації `__annotations__`) у функцію-обгортку (`wrapper`), щоб інструменти налагодження та документації бачили справжню функцію.

### 40. Чому потрібно оцінювати складність алгоритму?
**Відповідь:** Оцінка складності за допомогою нотації Big-O дозволяє передбачити масштабованість системи та поведінку програми під навантаженням на великих обсягах даних ще на етапі проектування архітектури, уникаючи критичних зависань та перевитрати ресурсів пам'яті.

## 21. Висновок

У ході виконання лабораторної роботи №2 було систематизовано та практично закріплено знання з вибору та використання вбудованих і спеціалізованих структур даних мови Python, а також принципів функціональної декомпозиції:

1. **Структури даних**: для індивідуального варіанта №9 («Облік спортивних результатів») успішно застосовано `list` (динамічний реєстр), `tuple` (незмінні метадані рекордів), `set` (унікальні категорії й дисципліни) та `dict` (асоціативні сутності та індекси).
2. **Модуль `collections`**: використання `Counter` дозволило лаконічно збирати статистику частот за видами спорту, `defaultdict` суттєво спростив однорівневе та вкладене групування, а `deque` забезпечив кільцевий буфер аудиту останніх викликів.
3. **Функціональні механізми**: програмний комплекс розділено на невеликі атомарні функції, реалізовано механізми гнучкого передавання аргументів (`*args`, `**kwargs`), анонімні вирази `lambda`, фабрики замикань (`closures`) та конвеєрну обробку (`pipeline processing`).
4. **Декоратори**: створено декоратор аудиту й вимірювання часу `@measure_time` та параметризований декоратор повторного виконання `@repeat(count)`.
5. **Теоретичний та експериментальний аналіз складності**: проведені бенчмарки на вибірках 1 000, 10 000 та 100 000 записів наочно продемонстрували перевагу індексації за допомогою хеш-таблиці `dict` ($O(1)$) над лінійним перебором у `list` ($O(n)$) із прискоренням до **397×**.

Отриманий модуль обробки структурованих даних є завершеним, повністю протестованим та готовим до інтеграції у наскрізні проекти наступних робіт курсу.
