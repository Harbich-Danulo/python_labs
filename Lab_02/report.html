2. Номер і тема лабораторної роботи

Лабораторна робота №2. «Структури даних та функціональна декомпозиція».

3. Мета роботи

Сформувати практичні навички професійного використання базових (list, tuple, set, dict) та розширених (collections.Counter, collections.defaultdict, collections.deque) структур даних Python, навчитися обирати оптимальну структуру відповідно до поставленої інженерної задачі, оцінювати асимптотичну часову складність основних операцій за допомогою нотації Big-O та проводити функціональну декомпозицію програми на невеликі функції з чітко визначеною відповідальністю. Опанувати роботу зі змінною кількістю аргументів (*args, **kwargs), анонімними функціями (lambda), замиканнями (closures) та декораторами (decorators).

5. Постановка задачі

Створити модуль обробки структурованих даних для варіанта №9 («Облік спортивних результатів»).

Вимоги до функціоналу:

  • прийом та збереження набору структурованих записів спортсменів (ID, ім'я, вид спорту, результат, категорія, кортеж незмінних метаданих);
  • використання списку (list), кортежу (tuple), множини (set) та словника (dict);
  • застосування спеціалізованих колекцій: Counter (підрахунок), defaultdict (одно- та багаторівневе групування), deque (кільцевий буфер історії операцій);
  • реалізація спискових включень (list/set/dict comprehensions) та генераторних виразів;
  • декомпозиція коду на спеціалізовані функції з використанням *args, **kwargs та lambda;
  • реалізація фабрики замикань (closure) для гнучкої фільтрації даних;
  • створення декоратора аудиту часу (@measure_time) та параметризованого декоратора (@repeat);
  • проведення теоретичного аналізу складності операцій та експериментального бенчмарку (List vs Dict) на наборах 1 000, 10 000, 100 000 записів.

7. Пояснення вибору list, tuple, set, dict

  • list: обрано для збереження головного впорядкованого динамічного реєстру спортсменів. Забезпечує додавання за амортизований час O(1), збереження черговості та гнучке сортування за допомогою Timsort за час O(n log n).
  • tuple: обрано для незмінних метаданих рекорду (тип досягнення, країна, рік). Гарантує цілісність інформації від випадкових змін, займає менше оперативної пам'яті, ніж список.
  • set: обрано для формування множин унікальних дисциплін і категорій. Дозволяє миттєво відсікати дублікати та виконувати перевірку належності за час O(1), а також підтримує теоретико-множинні операції (перетин &).
  • dict: обрано як для представлення окремого об'єкта спортсмена з іменованими полями, так і для побудови вторинних індексів за ID. Завдяки реалізації на хеш-таблицях забезпечує швидкий доступ O(1).

8. Приклад використання collections

У модулях проєкту застосовано три структури модуля collections:

  1. collections.Counter — підрахунок кількості спортсменів у дисциплінах: 
    sport_counts = Counter(item["sport"] for item in records)
  2. collections.defaultdict — групування спортсменів за категоріями та багаторівневе групування (вид спорту -> категорія -> список): 
    nested = defaultdict(lambda: defaultdict(list))
  3. collections.deque — кільцевий буфер фіксованої довжини (maxlen=20) для журналу останніх операцій у системі: 
    operation_history = deque(maxlen=20)

15. Пояснення closure (замикання)

Замикання (closure) — це внутрішня функція, яка запам'ятовує змінні зі свого лексичного контексту (зовнішньої функції) навіть після того, як зовнішня функція завершила своє виконання і була вилучена зі стека викликів.

def create_category_filter(category: str) -> Callable[[dict[str, Any]], bool]:
    target = category.strip().lower()  # Змінна зберігається в замиканні

    def predicate(athlete: dict[str, Any]) -> bool:
        return athlete["category"].strip().lower() == target
    return predicate

# Використання:
filter_senior = create_category_filter("Дорослі")
seniors = [a for a in athletes if filter_senior(a)]

Функція create_category_filter завершила роботу, однак згенерована функція predicate продовжує утримувати посилання на змінну target у своїй внутрішній комірці пам'яті __closure__.

16. Пояснення decorator (декоратор)

Декоратор — це шаблон проектування та синтаксична конструкція Python, що дозволяє динамічно розширювати функціональність існуючої функції без зміни її вихідного коду.

def measure_time(func: Callable[..., Any]) -> Callable[..., Any]:
    @wraps(func)
    def wrapper(*args: Any, **kwargs: Any) -> Any:
        start_time = perf_counter()
        result = func(*args, **kwargs)
        elapsed = perf_counter() - start_time
        print(f"[TIMING] {func.__name__}: {elapsed:.8f} s")
        operation_history.append(f"{func.__name__} executed in {elapsed:.8f} s")
        return result
    return wrapper

Декоратор приймає функцію func, обертає її у внутрішню функцію wrapper із заміром часу та реєстрацією в черзі deque, зберігає метадані функції через @wraps та прозоро повертає результат виклику.

20. Відповіді на контрольні запитання

1. Що таке list?
list — це впорядкована змінювана (mutable) динамічна послідовність довільних елементів з доступом за індексом.
2. Чим list відрізняється від tuple?
list є змінюваним (mutable), а tuple — незмінним (immutable). Кортежі займають менше пам'яті, працюють швидше та можуть бути ключами словника.
3. Чому tuple називається immutable?
Тому що після створення об'єкта tuple неможливо змінити його довжину або замінити посилання на елементи.
4. Для чого використовується set?
set використовується для збереження невпорядкованої колекції унікальних елементів, швидкої перевірки входження O(1) та математичних операцій над множинами.
5. Яка властивість елементів set є важливою?
Всі елементи множини повинні бути обов'язково хешованими (hashable) — реалізовувати незмінний метод __hash__() та метод рівності __eq__().
6. Що таке dict?
dict — це асоціативна структура даних, яка зберігає пари ключ-значення з високою швидкістю доступу за ключем.
7. Що таке key-value structure?
Це принцип зберігання даних, де доступ до кожного значення (value) здійснюється за його унікальним ідентифікатором — ключем (key).
8. Чому пошук key у dict зазвичай швидкий?
Оскільки dict побудовано на базі хеш-таблиці: індекс комірки обчислюється напряму через hash(key), забезпечуючи константний час O(1).
9. Що таке hashability?
Хешованість — це здатність об'єкта повертати незмінне числове значення хешу через функцію hash() протягом усього свого життєвого циклу.
10. Чому list не може бути key у dict?
Оскільки list є змінюваним (mutable) і не має методу __hash__(); зміна списку зробила б неможливим пошук елемента в хеш-таблиці.
11. Для чого використовується Counter?
collections.Counter призначений для автоматичного підрахунку кількості появ повторюваних елементів у послідовностях.
12. Для чого використовується defaultdict?
collections.defaultdict автоматично викликає функцію-фабрику для генерації значення за замовчуванням при зверненні до неіснуючого ключа.
13. Для чого використовується deque?
collections.deque (двозбічна черга) призначена для швидкого додавання та видалення елементів з обох кінців за гарантований час O(1).
14. Що таке list comprehension?
Лаконічний синтаксис для створення нових списків шляхом ітерації та фільтрації: [expr for item in iterable if cond].
15. Що таке set comprehension?
Синтаксис для створення множин унікальних елементів: {expr for item in iterable if cond}.
16. Що таке dict comprehension?
Синтаксис для створення словника пар ключ-значення: {k_expr: v_expr for item in iterable if cond}.
17. Що таке generator expression?
Лінивий генератор (expr for item in iterable), що генерує елементи по одному без завантаження всього набору в оперативну пам'ять.
18. Що означає O(1)?
Константна складність — час виконання операції не залежить від розміру вхідних даних n.
19. Що означає O(n)?
Лінійна складність — час виконання операції зростає прямо пропорційно до кількості елементів n.
20. Що означає O(n log n)?
Лінійно-логарифмічна складність — характерна для швидких алгоритмів сортування (наприклад, Timsort).
21. Що означає O(n²)?
Квадратична складність — час виконання зростає пропорційно квадрату обсягу даних (характерно для подвійних вкладених циклів).
22. Яка приблизна складність пошуку у list?
O(n) для несортованого списку, оскільки необхідно послідовно перевірити кожен елемент.
23. Яка середня складність пошуку у set?
O(1) у середньому завдяки прямому доступу через хеш-таблицю.
24. Яка середня складність пошуку key у dict?
O(1) у середньому завдяки адресації за хешем ключа.
25. Чому правильна структура даних може прискорити програму?
Зниження асимптотичної складності (наприклад, з O(n) на O(1)) кардинально зменшує кількість процесорних операцій на великих обсягах даних.
26. Що таке функціональна декомпозиція?
Розбиття складної програми на невеликі, логічно незалежні функції, кожна з яких виконує рівно одну задачу.
27. Які переваги малих functions?
Висока читабельність, простота покриття автоматичними юніт-тестами, легкість налагодження та можливість повторного використання.
28. Що таке positional argument?
Аргумент, значення якого передається у функцію згідно з його позиційним порядком у сигнатурі.
29. Що таке keyword argument?
Іменований аргумент, що передається у форматі ім'я=значення, що дозволяє передавати параметри в довільному порядку.
30. Для чого використовується *args?
Для прийому довільної кількості позиційних аргументів, які всередині функції пакуються в кортеж tuple.
31. Для чого використовується **kwargs?
Для прийому довільної кількості іменованих аргументів, які всередині функції пакуються в словник dict.
32. Що таке lambda function?
Коротка анонімна однорядкова функція: lambda args: expr.
33. Де доцільно використовувати lambda?
У функціях вищого порядку (як ключ сортування в sorted/max/min або простий предикат фільтрації).
34. Чому складну business logic не варто записувати в lambda?
Lambda обмежена одним виразом, не має зрозумілого імені для налагодження та погіршує читабельність коду.
35. Що таке closure?
Внутрішня функція, яка запам'ятовує змінні зовнішньої функції навіть після завершення роботи зовнішньої функції.
36. Які variables може пам'ятати closure?
Будь-які нелокальні змінні з області видимості зовнішньої функції, до яких звертається внутрішня функція.
37. Що таке decorator?
Функція вищого порядку, яка приймає іншу функцію та розширює її поведінку без зміни її вихідного коду.
38. Для чого застосовуються decorators?
Для профілювання часу виконання, логування, кешування результатів, аутентифікації та валідації вхідних даних.
39. Для чого використовується functools.wraps?
Для збереження імені (__name__), документації (__doc__) та анотацій оригінальної функції у функції-обгортці.
40. Чому потрібно оцінювати складність алгоритму?
Для прогнозування поведінки програми під навантаженням та запобігання зависанням і перевитратам пам'яті на великих даних.

21. Висновок

Під час виконання лабораторної роботи №2 було детально досліджено та практично реалізовано ключові принципи професійної роботи зі структурами даних та функціональної декомпозиції в Python:

  1. Структури даних: реалізовано комбіновану обробку даних за допомогою list, tuple, set та dict відповідно до індивідуального варіанта №9 («Облік спортивних результатів»).
  2. Модуль collections: використано Counter для аналітики розподілу за видами спорту, defaultdict для багаторівневого групування та deque для ведення історії операцій.
  3. Функціональні засоби: декомпозовано систему на невеликі функції, впроваджено *args, **kwargs, lambda, замикання (closures), конвеєрну обробку (pipeline) та декоратори (@measure_time, @repeat).
  4. Оцінка складності та бенчмарк: підтверджено теоретичну складність операцій на практиці. Пошук через хеш-індекс dict ($O(1)$) продемонстрував перевагу над лінійним перебором у list ($O(n)$) до **397.7 раза** на вибірці у 100 000 елементів.
