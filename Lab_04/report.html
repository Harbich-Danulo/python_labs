5. Опис предметної області

Предметна область охоплює облік та аналіз досягнень спортсменів на змаганнях різного рівня. Система забезпечує реєстрацію спортсменів, видів спорту, турнірів та фіксацію індивідуальних результатів. Змагальні результати мають різні метрики (бали, метри або секунди) та різні критерії лідерства (більший бал краще або менший час краще). Система формує рейтингові таблиці, розраховує агреговані статистичні показники та сповіщає зовнішні підсистеми про нові рекорди.

6. Список domain entities

  • Athlete — сутність спортсмена (ID, ім'я, країна, вік);
  • Sport — сутність спортивної дисципліни (ID, назва, одиниця вимірювання, прапорець виграшу: більше чи менше);
  • Competition — сутність змагання (ID, назва, місто/локація, рік);
  • Result — центральна сутність спортивного результату (композиція Athlete, Sport, Competition, Score);
  • RankingTable — контейнер рейтингу спортсменів зі стратегією сортування та dunder-методами.

8. Пояснення inheritance

Наслідування використано для реалізації патерну Strategy: базовий абстрактний клас RankingStrategy(ABC) визначає інтерфейс методу sort_results(), а підкласи HigherScoreWinsStrategy та LowerTimeWinsStrategy реалізують специфічні правила сортування. Це відповідає відношенню is-a та принципу Liskov Substitution Principle (LSP).

9. Пояснення composition

Композиція реалізує зв'язок has-a: сутність Result компонується з Athlete, Sport, Competition та Score; RankingTable містить список результатів та стратегію ранжування; а сервіс SportsAccountingService об'єднує репозиторії та протоколи сповіщень. Це забезпечує слабку зв'язаність компонентів (low coupling) та максимальну гнучкість системи.

13. Приклад immutable value object

@dataclass(frozen=True, slots=True)
class Score:
    value: float
    unit: str = "pts"

    def __post_init__(self) -> None:
        if self.value < 0:
            raise ValueError(f"Score value cannot be negative: {self.value}")

    def __add__(self, other: "Score") -> "Score":
        if self.unit != other.unit:
            raise ValueError(f"Unit mismatch: {self.unit} != {other.unit}")
        return Score(round(self.value + other.value, 4), self.unit)

17. Generic class

class InMemoryRepository(Generic[TEntity]):
    def __init__(self) -> None:
        self._items: dict[int, TEntity] = {}

    def add(self, entity: TEntity) -> None:
        self._items[entity.id] = entity

    def get(self, entity_id: int) -> TEntity | None:
        return self._items.get(entity_id)

22. Пояснення принципів SOLID

  • SRP: Клас Score відповідає виключно за значення та одиницю вимірювання, RankingStrategy — за алгоритм ранжування, SportsAccountingService — за бізнес-сценарії.
  • OCP: Нові правила сортування додаються через нові класи-нащадки RankingStrategy без зміни коду існуючих класів.
  • LSP: Підкласи HigherScoreWinsStrategy та LowerTimeWinsStrategy коректно замінюють базову абстракцію RankingStrategy.
  • ISP: Протоколи розділені на вузькі незалежні контракти (Identifiable, ScoredEntity, Notifier, ResultExporter).
  • DIP: SportsAccountingService залежить від абстракцій (Notifier, ResultExporter), а не від конкретних реалізацій поштових клієнтів чи файлових форматів.

28. Відповіді на контрольні запитання

1. Що таке class?
Клас — це шаблон (креслення), який описує структуру атрибутів та поведінку (методи) створюваних на його основі об'єктів.
2. Що таке object?
Об'єкт — це сутність у пам'яті комп'ютера, яка має стан, поведінку та унікальний ідентифікатор.
3. Що таке instance?
Екземпляр конкретного класу, створений за його описом.
4. Для чого __init__()?
Спеціальний метод-ініціалізатор, що налаштовує початковий стан екземпляра під час його створення.
5. Що таке instance attribute?
Атрибут, який прив'язаний до конкретного екземпляра об'єкта (зберігається в self.__dict__).
6. Що таке class attribute?
Атрибут, визначений на рівні самого класу, спільний для всіх його екземплярів.
7. Що таке encapsulation?
Принцип ООП, за яким внутрішній стан об'єкта захищається від прямого неконтрольованого зовнішнього втручання та змінюється лише через публічні методи.
8. Для чого properties?
Декоратор @property дозволяє звертатися до методу як до атрибута з можливістю контролю читання, зміни (setter) та видалення (deleter).
9. Чим property відрізняється від public field?
Доступ до звичайного поля не перевіряється, а property дозволяє виконувати валідацію та обчислення при присвоєнні або зчитуванні.
10. Що таке inheritance?
Механізм мови, що дозволяє одному класу успадкувати структуру й поведінку іншого класу для повторного використання або розширення.
11. Що означає relation is-a?
Відношення спеціалізації між класами (наприклад, HigherScoreWinsStrategy is-a RankingStrategy).
12. Що таке composition?
Принцип побудови складних об'єктів шляхом об'єднання простіших і незалежних об'єктів як своїх полів.
13. Що означає relation has-a?
Відношення володіння (наприклад, Result has-a Athlete, Car has-an Engine).
14. Коли composition краща за inheritance?
У більшості випадків проектування архітектури, коли поведінка може динамічно змінюватися під час виконання та потрібно уникнути жорсткої зв'язаності монолітних ієрархій наслідування.
15. Для чого super()?
Для виклику реалізації методів батьківського класу згідно з порядком MRO (Method Resolution Order).
16. Що таке polymorphism?
Здатність різнорідних об'єктів реалізовувати однаковий інтерфейс з власною специфічною поведінкою.
17. Що таке duck typing?
Принцип динамічної типізації: якщо об'єкт реалізує необхідний набір методів та властивостей, він вважається придатним для використання незалежно від його положення в ієрархії наслідування.
18. Що таке ABC?
Абстрактний базовий клас (Abstract Base Class), який не дозволяє створювати власні екземпляри і зобов'язує підкласи реалізувати методи, помічені @abstractmethod.
19. Для чого abstractmethod?
Декоратор, що позначає метод в ABC як обов'язковий до реалізації в усіх конкретних нащадках.
20. Чи можна створити instance abstract class?
Ні, спроба інстанціювати клас, що має нереалізовані абстрактні методи, викликає помилку TypeError.
21. Що таке Protocol?
Механізм структурної типізації (PEP 544), що дозволяє описувати інтерфейси без потреби явного успадкування.
22. Чим Protocol відрізняється від ABC?
ABC вимагає явного наслідування (номінальна типізація), а Protocol перевіряє лише відповідність сигнатур методів (структурна типізація).
23. Що таке structural typing?
Система типів, де сумісність визначається формою об'єкта (наявністю полів і методів), а не ім'ям його батьківського класу.
24. Що таке nominal typing?
Система типів, де сумісність перевіряється за явним деревом наслідування та назвою типу.
25. Що таке dataclass?
Декоратор стандартної бібліотеки, що автоматично генерує шаблонні методи класів (__init__, __repr__, __eq__) на основі оголошених анотацій типів.
26. Які methods генерує dataclass?
За замовчуванням: __init__, __repr__, __eq__, а за налаштуваннями — __hash__, __lt__, __gt__ тощо.
27. Для чого default_factory?
Функція для безпечної ініціалізації змінюваних значень за замовчуванням (field(default_factory=list)), щоб уникнути спільного використання одного екземпляра списку всіма об'єктами.
28. Чому mutable default є проблемою?
Якщо список чи словник оголошено як значення за замовчуванням у конструкторі, він створюється один раз під час завантаження модуля і модифікується спільно всіма екземплярами.
29. Для чого __post_init__()?
Хук у dataclass, що автоматично викликається після стандартного __init__ для виконання додаткової валідації чи розрахунку похідних полів.
30. Що означає frozen=True?
Робить об'єкт датакласу незмінним (immutable): спроба змінити атрибут викликає виняток FrozenInstanceError.
31. Що означає slots=True?
Замінює стандартний динамічний словник __dict__ фіксованим кортежем слотів __slots__, що зменшує споживання оперативної пам'яті та прискорює доступ до полів.
32. Що таке dunder method?
Спеціальний магічний метод із подвійними підкресленнями (double underscore), що інтегрує користувацький клас у стандартну об'єктну модель мови Python.
33. Для чого __repr__()?
Повертає однозначне офіційне строкове представлення об'єкта для розробника та налагодження.
34. Для чого __str__()?
Повертає зручне для читання користувачем представлення об'єкта.
35. Для чого __len__()?
Викликається вбудованою функцією len() для повернення розміру контейнера.
36. Для чого __iter__()?
Повертає ітератор над елементами об'єкта для використання в циклі for чи функціях ітерації.
37. Для чого __contains__()?
Реалізує роботу оператора перевірки входження in.
38. Для чого __call__()?
Дозволяє викликати екземпляр класу як звичайну функцію: obj().
39. Що таке SOLID?
Акронім 5 основоположних принципів об'єктно-орієнтованого проектування: Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation, Dependency Inversion.
40. Що означає SRP?
Принцип єдиної відповідальності: клас повинен мати лише одну причину для зміни.
41. Що означає OCP?
Принцип відкритості/закритості: програмні сутності мають бути відкритими для розширення, але закритими для модифікації.
42. Що означає LSP?
Принцип підстановки Лісков: об'єкти підкласу мають бути взаємозамінними з об'єктами базового класу без порушення коректності програми.
43. Що означає ISP?
Принцип розділення інтерфейсу: клієнти не повинні залежати від методів, якими вони не користуються; краще багато вузьких інтерфейсів, ніж один широкий.
44. Що означає DIP?
Принцип інверсії залежностей: високорівневі модулі не повинні залежати від низькорівневих; обидва мають залежати від абстракцій.
45. Що таке dependency injection?
Патерн, коли залежності передаються об'єкту ззовні (через конструктор чи метод), а не створюються ним самостійно всередині.
46. Чому DI покращує testability?
Дозволяє легко заміняти важкі зовнішні ресурси (бази даних, мережеві сервіси) легкими mock-об'єктами в тестах.
47. Що таке type hint?
Анотація типів, що вказує очікуваний тип змінної, параметра чи поверненого функцією значення.
48. Чи перевіряє Python type hints автоматично в runtime?
Ні, інтерпретатор ігнорує type hints під час виконання; вони слугують документацією для IDE та аналізаторів типів.
49. Що таке static type checker?
Інструмент (наприклад, mypy, Pyright), який аналізує код до запуску без виконання програми та знаходить невідповідності типів.
50. Для чого mypy?
Найпопулярніший офіційний статичний типізатор для Python.
51. Для чого Pyright?
Швидкий статичний типізатор від Microsoft, що лежить в основі розширення Pylance у VS Code.
52. Що таке TypeVar?
Змінна типу в Python, яка дозволяє писати параметрично поліморфний (generic) код.
53. Що таке Generic?
Базовий клас для створення параметризованих типів, що працюють з різними конкретними типами без дублювання логіки.
54. Що означає Generic[T]?
Вказує, що клас параметризований змінною типу T.
55. Що таке bound TypeVar?
Обмеження типу зверху: TypeVar('T', bound=SomeClass), яке дозволяє використовувати лише SomeClass або його підтипи.
56. Що таке constrained TypeVar?
Обмеження типу чітким фіксованим списком типів: TypeVar('T', int, float).
57. Що таке TypedDict?
Механізм опису фіксованої структури ключів та їхніх типів для звичайних словників dict.
58. Чим TypedDict відрізняється від dataclass?
TypedDict під час виконання залишається звичайним словником без поведінки та методів, а dataclass створює повноцінний екземпляр користувацького класу.
59. Коли доцільно використовувати TypedDict?
Для валідації зовнішніх вхідних payload-структур (JSON, конфігураційні файли, відповіді API) перед конвертацією в доменні сутності.
60. Чому external payload і domain object краще розділяти?
Для ізоляції бізнес-логіки від змін у форматах зовнішніх API. Якщо зовнішній сервіс змінить назву полів JSON, це не вплине на внутрішні доменні сутності, а вимагатиме лише зміни коду перетворення (парсингу).
