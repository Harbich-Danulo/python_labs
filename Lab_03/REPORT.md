## 8. Пояснення iterable та iterator

- **Iterable (ітерований об'єкт)** — це будь-який об'єкт, який реалізує магічний метод `__iter__()`, що повертає об'єкт-ітератор, або метод `__getitem__()` із підтримкою послідовної індексації з нуля. Приклади: `list`, `str`, `tuple`, `dict`, екземпляри класів-контейнерів.
- **Iterator (ітератор)** — це об'єкт потоку даних, який представляє поточний стан послідовного обходу. Він реалізує метод `__next__()` (який повертає наступне значення або піднімає виняток `StopIteration` при вичерпанні потоку) та метод `__iter__()` (який повертає сам об'єкт `self`).
- **Ключова відмінність:** Iterable можна обходити багаторазово (кожний виклик `iter()` породжує новий ітератор), тоді як Iterator є одноразовим об'єктом («one-shot object»), стан якого незворотно рухається вперед.

## 9. Код власного iterator

Реалізовано розділення контейнера (`SportsRange`) та незалежного ітератора (`SportsRangeIterator`):

```python
class SportsRangeIterator:
    """Власний ітератор, що реалізує протокол __iter__ та __next__."""
    def __init__(self, start: int, stop: int) -> None:
        self.current = start
        self.stop = stop

    def __iter__(self) -> "SportsRangeIterator":
        return self

    def __next__(self) -> int:
        if self.current >= self.stop:
            raise StopIteration
        val = self.current
        self.current += 1
        return val


class SportsRange:
    """Ітерований контейнер (Iterable), що породжує новий ітератор."""
    def __init__(self, start: int, stop: int) -> None:
        self.start = start
        self.stop = stop

    def __iter__(self) -> SportsRangeIterator:
        return SportsRangeIterator(self.start, self.stop)
```

## 10. Приклад generator function

```python
def clean_lines(lines: Iterator[str]) -> Iterator[str]:
    """Генераторна функція: ліниво очищає рядки від пробілів."""
    for line in lines:
        cleaned = line.strip()
        if cleaned:
```

## 11. Приклад yield

Ключове слово `yield` призупиняє виконання функції, запам'ятовує всі локальні змінні й поточний стан виконання стека та повертає поточне значення викликаючій стороні:
```python
def filter_by_sport(records: Iterable[SportsRecord], sport: str) -> Iterator[SportsRecord]:
    target = sport.strip().lower()
    for record in records:
        if record.sport.strip().lower() == target:
            yield record  # Повернення чергового елемента без збереження списку в пам'яті
```

---

## 12. Приклад yield from

Конструкція `yield from` делегує ітерацію іншому підгенератору або ітерованому об'єкту, усуваючи необхідність писати цикл `for item in sub_iterable: yield item`:
```python
def read_lines(path: Path) -> Iterator[str]:
    """Читання файлу з делегуванням рядків через yield from."""
    with path.open("r", encoding="utf-8") as file:
        yield from file
```

## 13. Generator expression

Генераторний вираз створює лінивий об'єкт-генератор за запитом, не матеріалізуючи список у пам'яті:
```python
# Потоковий розрахунок суми результатів стрибунів у висоту:
```

## 14. Використані засоби `itertools`

1. **`itertools.islice(iterable, stop)`**: зріз генератора без матеріалізації всього потоку (отримання перших $N$ записів).
2. **`itertools.pairwise(iterable)`**: ковзний аналіз пар послідовних елементів `(s0, s1), (s1, s2)...` для розрахунку динаміки спортивних результатів.
3. **`itertools.chain(*iterables)`**: послідовне об'єднання кількох незалежних генераторних потоків в один неперервний потік даних.

## 17. Validation stage

```python
def validate_records(rows: Iterable[dict[str, str]], invalid_counter: list[int] | None = None) -> Iterator[SportsRecord]:
    for row in rows:
        try:
            athlete = row.get("athlete", "").strip()
            sport = row.get("sport", "").strip()
            category = row.get("category", "").strip()
            timestamp = row.get("timestamp", "").strip()
            result_val = float(row.get("result", ""))

            if not athlete or not sport or not category or result_val < 0:
                if invalid_counter is not None:
                    invalid_counter[0] += 1
                continue

            yield SportsRecord(athlete, sport, result_val, category, timestamp)
        except (ValueError, TypeError, KeyError):
            if invalid_counter is not None:
                invalid_counter[0] += 1
            continue
```

## 20. Aggregation stage

```python
def streaming_average(records: Iterable[SportsRecord]) -> float:
    total = 0.0
    count = 0
    for r in records:
        total += r.result
        count += 1
    return round(total / count, 2) if count else 0.0
```

## 21. Batching stage

```python
def batched_records(records: Iterable[SportsRecord], batch_size: int) -> Iterator[list[SportsRecord]]:
    iterator = iter(records)
    while True:
        batch = list(islice(iterator, batch_size))
        if not batch:
            return
        yield batch
```

1. **Використання оперативної пам'яті:**

   - У lazy-підході пікова пам'ять залишається абсолютно стабільною на рівні часток мегабайта (~0.07–0.22 МБ), оскільки в пам'яті одночасно перебуває лише один поточний об'єкт `SportsRecord`. Економія пам'яті досягає понад **3484 разів**.
2. **Загальний час виконання:**
   - Eager-підхід дещо швидший за загальним часом повного обходу (5.90 с проти 9.68 с на 500k рядках) завдяки внутрішнім оптимізаціям C-коду списків та відсутності накладних витрат на регулярне перемикання генераторних контекстів і виклики `next()`.
   - **Висновок:** твердження «генератор завжди швидший» є помилковим; перевага генераторів полягає не в абсолютному часі, а в ефективності пам'яті.
3. **Швидкість отримання першого результату (`Time-to-first-result`):**
   - У lazy-підході перше відфільтроване значення доступне за 0.0003 с, тоді як eager-підхід вимагає повного очікування читання та парсингу всього файлу (5.9 с) перед поверненням хоча б одного елемента.

## 27. Контрольні запитання

### 1. Що таке iterable?
**Відповідь:** Це будь-який об'єкт у Python, з якого можна отримати ітератор за допомогою виклику `iter()`. Він реалізує метод `__iter__()` або `__getitem__()`.

### 2. Що таке iterator?
**Відповідь:** Це об'єкт, який зберігає стан обходу послідовності, реалізує метод `__next__()` для повернення наступного значення і метод `__iter__()`, що повертає `self`.

### 3. Чим iterable відрізняється від iterator?
**Відповідь:** Iterable — це джерело даних/контейнер, яке можна ітерувати багаторазово. Iterator — це сам вказівник обходу, який є одноразовим і вичерпується після проходження.

### 4. Для чого використовується iter()?
**Відповідь:** Для явного отримання об'єкта-ітератора з довільного ітерованого об'єкта (`iterable`).

### 5. Для чого використовується next()?
**Відповідь:** Для запиту наступного елемента в ітератора. Якщо елементи закінчилися, генерується виняток `StopIteration` або повертається значення за замовчуванням.

### 6. Що робить `__iter__()`?
**Відповідь:** В iterable повертає новий об'єкт-ітератор. В ітераторі повертає сам об'єкт `self`.

### 7. Що робить `__next__()`?
**Відповідь:** Обчислює та повертає наступне значення послідовності, пересуваючи внутрішній стан ітератора, або викликає `raise StopIteration`.

### 8. Що таке StopIteration?
**Відповідь:** Це стандартний виняток Python, який сигналізує про завершення доступних елементів в ітераторі.

### 9. Як цикл for використовує iterator protocol?
**Відповідь:** Спочатку викликає `iter()` над об'єктом, потім у нескінченному циклі викликає `next()` і автоматично перехоплює `StopIteration`, коректно завершуючи цикл.

### 10. Чому iterator часто називають one-shot object?
**Відповідь:** Тому що стан ітератора рухається лише вперед. Після того як він вичерпався, повторний обхід повертає порожній результат.

### 11. Чому `iter(iterator) is iterator`?
**Відповідь:** За ітераційним контрактом метод `__iter__()` ітератора завжди повертає `self`, що дозволяє передавати ітератор у будь-яке місце, де очікується iterable.

### 12. Чи можна повторно використати exhausted generator?
**Відповідь:** Ні, вичерпаний генератор не можна перезапустити. Для повторного обходу необхідно створити новий екземпляр генератора.

### 13. Що таке generator function?
**Відповідь:** Це функція, у тілі якої є хоча б один оператор `yield`. Її виклик повертає об'єкт-генератор, не виконуючи код тіла функції миттєво.

### 14. Яку роль виконує yield?
**Відповідь:** Повертає значення, призупиняє виконання функції та фіксує всі локальні змінні й поточний стан стека до наступного виклику `next()`.

### 15. Чим yield відрізняється від return?
**Відповідь:** `return` назавжди завершує роботу функції та звільняє її стек. `yield` заморожує стан функції з можливістю продовження з тієї самої точки.

### 16. Коли фактично починає виконуватися generator function?
**Відповідь:** Лише при першому виклику `next()` (або під час першої ітерації циклу `for`), а не під час виклику самої функції.

### 17. Що зберігає generator між викликами next()?
**Відповідь:** Поточну позицію інструкції (bytecode instruction pointer), локальні змінні, стек викликів та стан обробників винятків.

### 18. Що таке generator expression?
**Відповідь:** Це компактний вираз у круглих дужках `(expr for item in iterable)`, який повертає лінивий об'єкт-генератор.

### 19. Чим generator expression відрізняється від list comprehension?
**Відповідь:** `list comprehension` виділяє пам'ять під усю колекцію одразу. `generator expression` обчислює елементи по одному за запитом із мінімальним використанням пам'яті.

### 20. Що таке lazy evaluation?
**Відповідь:** Стратегія обчислень, за якої значення генерується лише в той момент, коли воно дійсно необхідне викликаючій стороні.

### 21. Що таке eager evaluation?
**Відповідь:** Стратегія «жадібних» обчислень, коли всі результати розраховуються та матеріалізуються в пам'яті повністю й негайно.

### 22. Які переваги lazy evaluation?
**Відповідь:** Мінімальне використання пам'яті (константний розмір), миттєвий доступ до перших елементів, можливість роботи з нескінченними потоками та підтримка early termination.

### 23. Які недоліки lazy evaluation?
**Відповідь:** Одноразовість обходу, відсутність індексації (`gen[i]`), неможливість миттєво дізнатися довжину `len()` та можливі накладні витрати на часте перемикання контексту генераторів.

### 24. Що таке streaming?
**Відповідь:** Потокова обробка даних невеликими порціями (рядками, блоками) без завантаження всього масиву у пам'ять.

### 25. Чому streaming важливий для великих files?
**Відповідь:** Оскільки розмір файлу може перевищувати доступний обсяг оперативної пам'яті комп'ютера, що призведе до помилки `MemoryError`.

### 26. Чому read() може бути проблемою для multi-GB file?
**Відповідь:** Метод `read()` зчитує весь вміст файлу в єдиний монолітний рядок у пам'яті, що викличе вичерпання RAM або зависання системи.

### 27. Чому file object є iterable?
**Відповідь:** Об'єкт файлу реалізує метод `__iter__()`, що повертає лінивий генератор рядків файлу через буфер вводу/виводу.

### 28. Для чого використовується yield from?
**Відповідь:** Для прозорого делегування генерації елементів вкладеному ітерованому об'єкту або підгенератору.

### 29. Що таке itertools?
**Відповідь:** Стандартний модуль Python, що містить високоефективні оптимізовані будівельні блоки для роботи з ітераторами.

### 30. Для чого itertools.count()?
**Відповідь:** Створює нескінченний генератор арифметичної прогресії чисел: `count(start, step)`.

### 31. Чому count() потрібно обмежувати?
**Відповідь:** Тому що спроба передати його у `list()` спричинить нескінченний цикл і переповнення пам'яті.

### 32. Для чого islice()?
**Відповідь:** Для виконання зрізу по ітератору `[start:stop:step]` без завантаження всієї послідовності в пам'ять.

### 33. Для чого chain()?
**Відповідь:** Для об'єднання декількох послідовностей в один безперервний ітератор.

### 34. Як працює takewhile()?
**Відповідь:** Повертає елементи послідовності, доки умова-предикат істинна, і негайно зупиняється при першому `False`.

### 35. Як працює dropwhile()?
**Відповідь:** Пропускає елементи, доки умова істинна, а після першого `False` повертає всі наступні елементи до кінця.

### 36. Для чого accumulate()?
**Відповідь:** Для обчислення накопичувальних підсумків (кумулятивної суми тощо).

### 37. Для чого pairwise()?
**Відповідь:** Для попарного обходу послідовності `(item0, item1), (item1, item2)...` з перекриттям.

### 38. Як працює groupby()?
**Відповідь:** Групує поспіль розташовані елементи з однаковим ключем.

### 39. Чому перед groupby() часто потрібне sorting?
**Відповідь:** Тому що `groupby` згортає лише суміжні елементи з однаковим ключем. Якщо однакові ключі розкидані по списку, вони сформують різні групи.

### 40. Що робить product()?
**Відповідь:** Обчислює декартовий добуток вхідних послідовностей.

### 41. Чим combinations() відрізняється від permutations()?
**Відповідь:** `combinations` не враховує порядок елементів (групи унікальні за складом), а `permutations` повертає всі можливі перестановки з урахуванням порядку.

### 42. Чому combinatorial iterators можуть бути небезпечними навіть при lazy execution?
**Відповідь:** Через комбінаторний вибух: кількість згенерованих елементів зростає факторіально або експоненційно, що призведе до гігантського часу виконання.

### 43. Що таке batching?
**Відповідь:** Групування елементів потоку у фіксовані пакети (наприклад, по 1000 записів) для масової обробки.

### 44. Які переваги batching?
**Відповідь:** Зменшення мережевих накладних витрат при роботі з БД чи API та підвищення ефективності вводу/виводу.

### 45. Що таке lazy pipeline?
**Відповідь:** Ланцюг генераторних функцій, де кожен етап бере один елемент від попереднього, обробляє його і передає далі.

### 46. Які stages може містити pipeline?
**Відповідь:** Читання (`source`) $\to$ парсинг $\to$ валідація $\to$ фільтрація $\to$ трансформація $\to$ пакетування $\to$ агрегація/запис (`sink`).

### 47. Що є source у streaming pipeline?
**Відповідь:** Первинний постачальник даних: файл, сокет, черга повідомлень або нескінченний генератор.

### 48. Що є transformation?
**Відповідь:** Проміжна генераторна стадія, що змінює формат чи структуру кожного окремого запису.

### 49. Що є sink?
**Відповідь:** Кінцевий споживач потоку, який запускає виконання конвеєра: агрегатор (`sum()`, `count()`) або запис у файл чи базу даних.

### 50. Чи гарантує generator менший total execution time?
**Відповідь:** Ні. Часто генератор працює трохи повільніше через накладні витрати на перемикання контексту функції.

### 51. Яка основна memory advantage generator?
**Відповідь:** Константне використання пам'яті $O(1)$, яке не залежить від кількості оброблюваних записів.

### 52. Що таке time to first result?
**Відповідь:** Час від моменту старту програми до моменту отримання викликаючою стороною найпершого валідного результату.

### 53. Чому lazy pipeline добре підтримує early termination?
**Відповідь:** Обчислення виконуються за запитом. Якщо нам потрібен лише один елемент, обробку можна перервати після першого знайденого збігу без читання решти гігабайтів файлу.

### 54. Чому exception у generator може виникати із затримкою?
**Відповідь:** Оскільки код тіла генератора не виконується при створенні об'єкта, а лише тоді, коли споживач дійде до проблемного рядка через `next()`.

### 55. Чому list(generator) може бути проблемою?
**Відповідь:** Це примусово матеріалізує весь потік у пам'яті, повністю знищуючи перевагу генератора в економії RAM.

### 56. Що трапиться при list(count())?
**Відповідь:** Програма зависне в нескінченному циклі й завершиться аварійно через `MemoryError`.

### 57. Як generator може впливати на lifecycle file resource?
**Відповідь:** Якщо генератор не вичерпано до кінця, блок `with open(...)` всередині нього залишатиме дескриптор файлу відкритим, доки збирач сміття не видалить об'єкт генератора.

### 58. Як тестувати невеликий generator?
**Відповідь:** Шляхом матеріалізації його результату у звичайний список `list(gen)` та перевірки значень через стандартні `assert`.

### 59. Як тестувати infinite generator?
**Відповідь:** Обмежуючи кількість генерованих елементів за допомогою `itertools.islice(gen, N)`.

### 60. Коли краще використовувати list, а коли generator?
**Відповідь:** `list` кращий, коли потрібен швидкий доступ за індексами, багаторазовий обхід або вибірка невелика. `generator` кращий, коли набір даних великий, не поміщається в пам'ять, надходить потоково або потрібне дострокове припинення обробки.

## 28. Висновок

Під час виконання лабораторної роботи №3 було успішно опановано ітераційну модель Python, принципи відкладених обчислень та побудову високоефективних потокових конвеєрів:

1. **Ітератори та протокол:** створено власний клас ітератора `SportsRangeIterator` та контейнера `SportsRange`, що закріпило розуміння взаємодії `__iter__()`, `__next__()` та винятку `StopIteration`.
2. **Генераторний конвеєр:** розроблено лінивий конвеєр обробки спортивних результатів за варіантом №9, що включає фази читання (`read_lines`), парсингу, валідації (`validate_records`), лінивої фільтрації, нормалізації та пакетування (`batching`).
3. **Модуль `itertools`:** ефективно застосовано інструменти `islice` (зріз без матеріалізації), `pairwise` (попарний аналіз різниць результатів) та `chain` (об'єднання потоків).
4. **Порівняльний аналіз пам'яті та часу:** практичні вимірювання на вибірках до 500 000 записів продемонстрували колосальну перевагу lazy-підходу за піковою пам'яттю (економія у **3484 рази** на 500k рядках: 0.07 МБ проти 243.9 МБ). Водночас підтверджено, що lazy-підхід забезпечує практично миттєве повернення першого результату (0.0003 с проти 5.9 с).

Отримані знання дозволяють будувати промислові масштабовані системи аналізу даних, що працюють з великими файлами в умовах обмежених ресурсів оперативної пам'яті.
